# Image generation prompts

Generate images at `assets/images/<category>/<name>.png` using a reusable ComfyUI workflow — one
template and one prompt per image.

**`category` is the event name** (`eventName` in the `event_images` table, the same key used by the
API at `GET /events/:eventName/image`) — for example, `posse`, `comicio`, `eleicao`, `atentado`,
`morte`. An event can have **more than one image**: add another manifest entry with the same
`category` and a different `name` (for example, `comicio/palanque.png` and `comicio/multidao.png`);
the API picks one at random per request (`findImageForEvent`, `ORDER BY random()`). After generating,
register each `fileLocation` in `apps/api/src/db/seed.ts` under the same `eventName`.

- **`_base.api.json`** — the template in ComfyUI API format. It has one positive prompt node (text
  `"{{PROMPT}}"`), a fixed negative prompt (blocks graphic violence/blood, design document §6), and
default parameters from the table below. Do not edit this file's prompt directly — the script clones
and fills it each time.
- **`_base.workflow.json`** — the same pipeline in ComfyUI **UI format** (nodes/links/positions), for
  visual editing in ComfyUI Desktop (drag the file into the app window or choose File → Open
  Workflow). Use this to test prompts manually before adding them to the manifest.
- **`manifest.json`** — the list of images to generate: `{ "category", "name", "prompt", "seed"? }`
  per entry. `seed` is optional (if omitted, the template seed is retained). Each entry generates
  `images/<category>/<name>.png`.

Images appear after major events (design document §8). The tone is a "serious simulation":
repression appears in a restrained way, without graphic violence, blood, or injuries (design document
§6). Therefore the negative prompt is fixed in the template and **does not belong in the manifest**.

## Prerequisites

1. **ComfyUI running** at `127.0.0.1:8188` (ComfyUI Desktop or `comfy launch`).
2. **Checkpoint installed:** download `RealVisXL_V5.0_Lightning_fp16.safetensors` (distilled SDXL,
   about 6.9 GB) from https://huggingface.co/SG161222/RealVisXL_V5.0_Lightning and place it in the
   ComfyUI `models/checkpoints/` directory. No VAE, LoRA, or custom nodes are needed. If ComfyUI was
   already open before downloading, restart it (the checkpoint directory is read at startup).
3. **Repository dependencies installed:** run `pnpm install` at the root (installs
   `tools/generate-images`).

## Default workflow parameters

| Parameter | Value |
|---|---|
| Resolution | 1088×1024 (event screen aspect ratio) |
| Steps | 6 |
| CFG | 1.5 |
| Sampler / scheduler | `dpmpp_sde` / `karras` |

## Generate images

### 1. Add manifest entries

Edit `assets/prompts/manifest.json` and add one entry per image:

```json
{
  "category": "atentado",
  "name": "tentativa",
  "prompt": "cinematic video game screenshot, Unreal Engine 5, photorealistic. ..."
}
```

- `category`: event name (`eventName`), lowercase, letters/numbers/hyphens only (`[a-z0-9-]+`). Use
the same `category` in multiple entries to give **one event multiple images**.
- `name`: identifies a variant within the event (lowercase, `[a-z0-9-]+`). Together with `category`,
it determines the output path `assets/images/<category>/<name>.png`.
- `prompt`: positive prompt **only**. The negative prompt (blocks graphic violence/blood, design
document §6) is fixed in the template and should not be repeated here.
- `seed` (optional): a fixed number to reproduce a specific generation; if omitted, the template
  seed (`_base.api.json`) is used.

The manifest already contains the **100 entries from the design document**: one node per policy tree
(S1, including an illustrative entry for tax intensity variants), plus the universal main-loop events
(`posse`, `comicio`, `eleicao`, `atentado`, `morte`, `golpe-militar`, `prisao-oposicao`). The script
processes them one at a time.

### 2. (Optional) Test the prompt in ComfyUI Desktop before running the batch

Open `assets/prompts/_base.workflow.json` in ComfyUI Desktop (drag it into the app window or choose
File → Open Workflow), edit the "Prompt positivo" node text, click "Run", and inspect the result. It
is the same pipeline used by the script, in a visual format for quickly testing a seed or prompt
without editing the manifest.

### 3. Run the script

With ComfyUI open (prerequisite 1):

```bash
pnpm --filter @decreto/generate-images generate
```

The script reads `assets/prompts/manifest.json`; for every entry it clones `_base.api.json`, sets the
prompt/seed/output path, queues the job in ComfyUI (`POST /prompt`), waits for completion
(`GET /history/<id>`), and downloads the PNG (`GET /view`) directly to
`assets/images/<category>/<name>.png` — no manual file copying. Entries whose output file already
exists are skipped (`[skipped] ...` log); new ones are reported as `[generated] ...`.

Because local ComfyUI runs one job at a time, images are generated **sequentially**, not in parallel.
For 100 entries, expect approximately 100 × the time per image (see the "Machine" section below).

| Flag | Effect |
|---|---|
| `--only <name>` | Generate only the entry with this `name`; skip the others |
| `--force` | Regenerate even if the output file already exists |
| `--comfy-url <url>` | Use another ComfyUI server (default: `http://127.0.0.1:8188`, or `COMFYUI_URL` env var) |
| `--manifest <path>` | Use another manifest file (default: `assets/prompts/manifest.json`) |

```bash
# Generate (or regenerate) one entry, even if the output file exists
pnpm --filter @decreto/generate-images generate -- --only tentativa --force

# Use another ComfyUI server (for example, another machine on the network)
pnpm --filter @decreto/generate-images generate -- --comfy-url http://192.168.1.10:8188
```

### Common errors

- `ComfyUI rejected the prompt: ...` — ComfyUI is not running at `127.0.0.1:8188`, or the checkpoint
  is not installed/visible (restart ComfyUI after placing it in `models/checkpoints/`).
- `Timed out waiting for prompt ...` — generation took more than 5 minutes (default); check
  the ComfyUI queue, as another heavy job may be ahead of it.
- `ComfyUI returned no image for "<name>"` — the workflow ran but the `SaveImage` node produced
  no output; check the ComfyUI log for the underlying error.

## Machine

- **M2 16 GB** (used for these generations): about 2 min per image, 3.5 min for the first (model
  loading). Z-Image Turbo bf16 **does not run** — it needs about 19.4 GB (11.7 GB model + 7.7 GB
  text encoder).
- **M4 Pro:** use `batch_size` 2–4 to choose between variations. With 48 GB of memory, Z-Image Turbo
  bf16 fits and tends to produce more realism, but requires another workflow (diffusion model +
  Qwen3-4B text encoder + `ae` VAE), CFG 1, and ignores the negative prompt. With 24 GB it is near the
  limit — RealVisXL is preferred.
